# .NET numeric and project-root import parity — draft 2026-10-18

Issues #35 (f32/f64/BigInt/Decimal/Matrix CIL and Native AOT) and #38 (canonical `+/` module graph).

## Numeric contract
- Keep checked i64 lowering separate from IEEE binary32/binary64 with NaN, infinities and signed-zero preserving operators.
- BigInt/Decimal literal parsing and arithmetic must be exact without lossy double intermediary or hidden culture-dependent parsing.
- Matrix shapes, stride, extent and ownership are checked before allocation; no uncaught CLR exception should be presented as language-defined error semantics.
- Native AOT receipts must bind CLI/compiler SHA, source/tree SHA, emitted CIL/PE digest and execution status. CLR-only tests cannot certify AOT parity.

## Import graph contract
- Root-relative `+/` imports are canonicalized independently of current directory and sorted before signature/digest computation.
- Reject traversal, symlink escapes, cycles, duplicate identity under case folding and runtime side effects during import.
- Binder emits a stable declared module identity; link failures must produce a source-level diagnostic.

## Negative corpus
1. `i64::MAX + 1` remains overflow checked, not wrapped.
2. Decimal `0.1 + 0.2` exact; f64 behaves per IEEE.
3. A 2x3 matrix cannot be consumed as 3x2 without explicit transpose.
4. A `+/../../` import and symlink escape reject.
5. Module cycle and duplicate canonical path reject.
6. Native AOT build results do not inherit host interpreter outcomes.

**Status:** audit vectors and acceptance gates; compiler features and runnable CIL/AOT parity not completed here.
