# Inline task and root task CIL

The normal `.atto` `check` and `compile` commands accept `sync task<T>` expressions for supported scalar and tagged result types. The body stays in the caller's verified CFG. Its explicit `return` or `^` branches to the inline continuation. The value form can read surrounding locals. `do sync task` executes a void body, can update surrounding mutable locals, and supports either fallthrough or an explicit void return.

Inline code runs on the caller thread and creates no task or Future. In a standalone root guest, `rt cooperate;` offers the current OS time slice and returns on that thread. A guest-scheduler handoff that can run another logical task on the same carrier still needs runtime integration. The compiler rejects an `await` without a same-thread continuation, unsupported effects and a void task used as a value. A value-context inline task used as the complete initializer of a runtime local now joins the surrounding mutable SSA bindings with its result. Both branch exits and nested typed/void tasks preserve writeback. Nested expression writeback (including short-circuit RHS and arithmetic operands), inline postfix propagation, trapping an outlined inline task with side effects, and general `defer` resource cleanup remain rejected until their effect-aware CFG joins are implemented.

The explicitly selected `compile-task-i64` profile accepts `val Future<int> f = task<int> { return ...; }; return await f;` in a `susp` root `main`. Its capture-free arithmetic producer is compiled to CIL and scheduled by the bounded root-task host. The host observes its Future once and waits for physical retirement before completing. The existing `Future.from_task` wrapper form stays available in the opt-in profile. Arbitrarily many tasks, captured producers, suspension inside a producer, and actor task scopes require the general task emitter and scheduler integration.

`ci/test-task-inline-cil.sh` executes compiled inline cases and the separately scheduled typed child on CoreCLR or standalone macOS ARM64 NativeAOT. It checks that incompatible inline source emits no CIL.

## Guard integration boundary

Both ordinary guard forms require an enclosing callable return on every failure path. The inline-task and imperative-match local return machinery must not silently retarget those returns to a lexical join. The admitted cleanup-free scalar/tagged CFG now targets the enclosing callable directly for guard failure, even inside a nested inline task or imperative match. Ordinary local returns still target their lexical join. General resource cleanup remains unsupported. Guards in the enclosing callable can be composed with inline tasks and trapped Result values. The integration fixture covers both guard spellings, trap success and division failure, and an inline match. Both runtime lanes run the new guard-nonlocal guest (both spellings, nested void tasks, imperative match and tagged callable return) and reject four malformed failure arms with diagnostic-specific check/compile denials and no guest DLL.

The preflight suspension gate distinguishes await inside a braced inline task from await outside it, without admitting either. The negative suite verifies nested typed inline bodies and that the diagnostic does not leak past the closing task brace. Diagnostic mismatches now print the fixture, status and captured compiler output.

The legacy terminal overflow catch profile cannot be used in a lexical task or imperative match arm, because its CIL CFG ends in a callable return. Reject such scopes with `E_LOCAL_TRY_RETURN_UNSUPPORTED`. `defer` and `using` statements in lexical or guard failure scopes are explicitly denied with `E_LEXICAL_CLEANUP_UNSUPPORTED` until a verified unwind continuation is available. No cleanup is silently elided. The dual-lane denial harness checks five new cases.

Current-main integration combines the exact five changed paths of #249 (canonical scheduled root task) with the #252 Result/guard parent and inline CFG. Main's authenticated Core source admission, checked shifts, typed const rules and loop stack remain intact. Lexical task/match loop transfers and linked inline task admission remain denied. The former Result guard-in-match rejection becomes a positive nonlocal callable-return guest. Imperative match inside a guard failure is still conservatively denied. These are proposed compiler changes; require new exact-head execution.

Canonical suspension-permission spelling `suspends fnc` is now admitted by the standalone inline-task profile (legacy `susp` retained). This does not authorize `await`, `critical suspends`, `async`, linked suspension, or general suspendable scalar entrypoints. Token-aware preflight distinguishes inline and outer await, and comment-only task text never enables the profile. Both guest lanes exercise one long-marker success and four diagnostic-specific no-artifact denials; the boundary unit test also retains the old scalar rejection.

### Lexically owned loops

A task or imperative match arm may now break or continue a loop opened within that same lexical return scope. Record the loop depth on scope entry and require a strictly deeper loop at each transfer. Existing CFG loop-target stack and typed SSA join carry mutable scalar and Option state across continue/break. Crossing into a pre-existing enclosing loop remains rejected, even between nested tasks. Guard failure still cannot use a loop transfer as its callable-return proof. Dual-lane positive and negative cases cover local loops, nested task boundary and match boundary. Exact-head execution pending.

### Complete mutable assignment RHS

The same statement-value gate now admits complete `let` assignment RHS tasks, including scalar and Option results. The existing StructuredSet lowering evaluates the entire RHS and publishes SSA writeback before installing the assignment's final result; a write to the destination within the task is therefore overwritten by the final assignment. The parser still denies nested arithmetic, short circuit, inherited write floors, immutable destinations, const and comma-body declaration writeback. AST shape is checked after lexical selection. Both guest profiles include a multi-branch scalar/Option positive and three no-artifact denials. Exact-head execution required.

### Bounded short-circuit statement writeback

A complete runtime declaration or mutable assignment may use a top-level `and`/`&&` or `or`/`||` with an immediate inline task as its RHS. The skipped edge passes the original SSA environment and tested boolean; the evaluated edge passes the task-updated environment and resulting boolean. Typed join parameters preserve both Option tag and payload. The parser validates the final AST root and retains inherited write floors; parenthesized/nested short-circuit writeback, additional RHS operators, trap outlining and arbitrary expression contexts remain denied. The dual-lane suite exercises both truth values for AND and OR, scalar and tagged writes, and two additional diagnostic denials; prior short-circuit denials now target nested expressions outside the admitted subset. New exact-head CI required.

### Bounded conditional statement writeback

Complete runtime declaration or mutable assignment values may use keyword `if ... then ... else ... fi` (including ifnot/unless) with immediate complete sync-task arms. The parser owns the permission at the outer conditional's offset, validates the final AST, and retains inherited write floors. Branches have independent SSA environments, and LexicalContinuation joins result and mutable bindings, splitting closed Option tags and payloads. Untaken arms do not execute. Nested conditional writes, arithmetic arms, ternary writeback, pending awaits and cleanup remain denied. Both guest profiles target one scalar/Option four-way fixture plus three diagnostic denials. New exact-head execution required.

### Bounded match statement writeback

Complete mutable assignment or runtime declaration values may use a value match with immediate semicolon-terminated sync-task arms. The parser grants permission only at the root match offset and verifies the resulting AST. Existing exhaustiveness, immutable binders, pure pattern/guard selection and per-arm environments remain intact. The lexical continuation joins the result plus outer mutable scalar and Option bindings; arm binders never escape. Subject, guard, nested arm expressions and inherited restricted scopes cannot publish writes. A four-path runtime fixture exercises guarded fallthrough and Option payload binders; four new diagnostic denials cover forbidden contexts. Exact-head execution required.

### Bounded ternary statement writeback

A complete runtime declaration or mutable assignment may also use `condition ? task-arm : task-arm` with immediate complete sync-task branches. The parser uses the statement entry offset and arm delimiters to grant permission; the final AST must still be the conditional root. Existing keyword conditional typed continuation joins apply unchanged, including closed Option tags and payloads. The false arm keeps the existing right-associative Conditional parser. Predicate, nested arithmetic, nonroot conditionals and inherited restricted scopes cannot publish writes. New four-path fixture and four denial fixtures are registered in both guest lanes. Exact-head execution pending.

### NativeAOT regression repair: prefix logical not

The #257 and #258 task jobs failed at offset 338 of inline-shortcircuit-writeback.atto, the `!result` token. The structured parser already has typed boolean negation, but the standalone lexer admitted only a bang followed by `(`. Admit the standalone bang after the existing multi-character operators and ownership handling, without altering macro preflight or `!=` / `!eq` precedence. Preserve the failed fixture verbatim. Add a dedicated guest for adjacent and spaced prefix not and both inequality spellings, plus nonbool, macro and ownership denials. Parenthesized bang remains conservatively gated by the existing macro preflight; this repair does not expand macro admission. Exact-head rerun required.

### Parenthesized logical negation admission

Separate prefix `!(bool-expression)` from unsupported macro invocation using a narrow token-context predicate. Prefix punctuation and separated expression-introducing keywords admit boolean operands; adjacent keyword macro-like forms and identifier-led invocations (including spaced bang) retain the existing macro diagnostic. Typed Unary checks bool and now uses CheckedConditional to account for the AST height. No macro or ownership lowering is added. A dedicated native/managed guest plus three no-artifact denials and structured parser assertions exercise the boundary. This is a separate candidate so the prefix-not regression repair can finish its exact-head CI unchanged.
